# Cockpit Copilot · 智能座舱 AI Agent

> 产品经理作品 | 王瑞琪 | 2026.05

## 一句话概述

基于 LLM 的智能座舱自然语言交互 Agent，支持多模态意图识别、function calling 与三层置信度决策机制。

---

## 项目背景

### 问题洞察（来自 201 所实习）

在智能座舱"一控多"场景下，操作员需同时控制本车与 30+ 无人设备，操作链路长、步骤繁琐。**根因在于交互逻辑沿用单机思维，认知负荷远超操作员承载上限。**

### 设计假设

如果座舱内有一个 AI Agent，能理解自然语言指令，自动完成 80% 常规操作，只在不确定时请求人工确认——认知负荷能降低多少？

### 项目目标

- 验证「一键触发 + 异常干预」防御式设计在座舱场景的可行性
- 设计一个可交互的 Agent 原型，展示从意图识别到功能触发的完整闭环
- 探索 AI Agent 在复杂 B 端操作台中的交互范式

---

## 核心功能

| 模块 | 支持指令示例 | 实现方式 |
|------|-------------|---------|
| 🌡 温度控制 | "有点冷""调到 24 度""好热" | 上下文感知：自动判断升温/降温幅度 |
| 🔥 座椅加热 | "打开座椅加热""加热关掉" | 关联温度上下文，低温时主动建议 |
| 🗺 导航 | "导航到充电站""回家""去公司" | 关键词匹配 + 目的地模糊识别 |
| 🎵 媒体 | "放点轻音乐""播放摇滚" | 按风格分类匹配歌单 |
| 💡 氛围灯 | "灯光蓝色""氛围灯暗一点""关灯" | 9 色映射 + 亮度调节 |
| 🚗 驾驶模式 | "切换运动模式""节能模式" | 4 种模式 + 模式转换建议 |

## 设计亮点

### 1. 三层置信度决策机制

| 置信度 | 行为 | 示例 |
|--------|------|------|
| ≥ 80%（高） | **自动执行**，通知结果 | "调至 24°C"→ 直接调温 |
| 60-79%（中） | 执行后**附带确认** | "运动模式 + 红色氛围灯，可以吗？" |
| < 60%（低） | **不执行**，列出选项请求确认 | "您是关氛围灯还是调暗仪表盘？" |

> 设计哲学：80% 常规操作 Agent 自动处理，20% 安全/模糊决策保留人控。

### 2. 上下文感知

- **时间感知**：夜间自动建议调暗仪表盘、开启柔白氛围灯
- **天气关联**：雨天建议开启雾灯、雪天建议切换雪地模式（预留）
- **状态关联**：运动模式自动建议红色氛围灯；低温自动建议座椅加热
- **偏好记忆**：「跟上次一样」→ 调取历史配置组合（预留）

### 3. 复合意图处理

用户自然语言中同时包含多个意图时的拆解逻辑：
> "切换到运动模式，氛围灯调成红色" → Agent 识别为 2 个独立 function call → 批量执行 → 统一确认

### 4. 模糊意图的降级策略

> "有点暗" → Agent 不确定是指氛围灯还是仪表盘 → 列出 2 种可能 → 让用户选择
> 这是 PM 需要思考的核心问题：**Agent 说「我不知道」的场景比 Agent 瞎猜更重要。**

## 技术实现

| 层级 | 技术方案 |
|------|---------|
| 前端 | 纯 HTML/CSS/JS，零依赖，浏览器直接打开 |
| 布局 | CSS Grid + Flexbox，响应式 |
| 动画 | CSS Animation（仪表盘、均衡器、导航路径） |
| Agent 引擎 | 前端本地规则匹配（模拟 LLM function calling） |
| 状态管理 | 纯 JS object，观测者模式更新 UI |

### 为什么先用规则匹配而非接真实 LLM？

1. **面试可离线演示**，不依赖网络和 API Key
2. **意图识别逻辑透明**，面试官能看到完整的决策链路
3. **规则本身体现了产品思维**——如何把模糊的自然语言映射到结构化操作

下一步：接入 OpenAI API 实现真实 LLM 调用（代码已预留接口）

## 使用方法

1. 浏览器打开 `index.html`
2. 在右侧对话框输入自然语言指令
3. 或点击底部快捷词条快速体验
4. 点击顶部「演示模式」自动播放完整对话流程
5. 观察左侧仪表盘实时响应
